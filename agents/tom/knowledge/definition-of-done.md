# Definition of Done

<!-- Owner: tighten these rules to match your release process. Tom treats this file as the bar for opening a PR. -->

- **Tests green:** run the repo's test command from `knowledge/repos.md`; include the exact command and result in the PR.
- **PR description:** use this structure in plain English: Symptom -> Cause -> Fix -> Proof.
- **No unrelated diffs:** changes must match the posted plan; drive-by cleanup waits its turn.
- **Branch discipline:** work happens on `tom/<taskid>` only; never push to `main` or `master`, never merge, never force-push.
- **Owner-readable summary:** the final `#dev` update should say what changed and why it matters in three sentences.
